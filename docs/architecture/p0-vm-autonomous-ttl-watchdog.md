**Scope:** HOMESV `light-luna-p0-nftvm` (LXD KVM VM, separate Linux kernel, NIC-less). Development-only synthetic nft table, not product kernel enforcement.
**Date:** 2026-10-14. Branch `feat/p0-standalone-foundation`.
**Status:** **3/3 consecutive full KVM VM suites PASS after the final keeper/cleanup fix**. The automatically triggered synthetic rollback was observed in all three runs, including restored IPv4/IPv6 TCP/UDP. No production or G-STANDALONE claim.

## Core P0 primary/fallback DONE temporal consistency — offline RED→GREEN (2026-10-15)

**VM-ONLY, PURE READ-ONLY CLASSIFICATION; NOT A RUNNING WATCHDOG PROOF.** The previous [DONE contract reviewer](../../scripts/lab/vm/guest-rollback-review.py) required matching `deadlineMonotonic` between READY and DONE and finite time values, but did **not** require `completedMonotonic >= deadlineMonotonic`. It also accepted an arbitrary finite, nonnegative `lagSeconds` for the primary DONE even when that number disagreed with the primary producer's actual `max(0.0, completedMonotonic - deadlineMonotonic)` formula. Both the [primary watchdog](../../scripts/lab/vm/guest-auto-watchdog.py) and [fallback supervisor](../../scripts/lab/vm/guest-fallback-supervisor.py) wait until the monotonic deadline before rollback, so their emitted DONE completion cannot precede that deadline under normal same-boot monotonic-clock semantics.

[The read-only reviewer](../../scripts/lab/vm/guest-rollback-review.py) now requires completion **at or after** the matching deadline for both producers and requires the primary `lagSeconds` to equal the computed value from the same DONE timestamps. The check uses Python float arithmetic matching the producer's JSON serialization; this is a strict **internal data consistency check**, not a timing performance SLA, trusted clock attestation or a receipt signature.

[Offline regressions](../../scripts/lab/vm/test_rollback_review.py) reproduced **five RED negative subcases** before the fix: primary/fallback completion before deadline (2) and wrong primary lag (3). After the source change all five are GREEN; properly matched positive primary/fallback fixtures pass, including a later valid completion. **30/30 focused reviewer tests and 115/115 Python VM offline tests PASS.** Previously documented real KVM tests are historical and were **not** rerun; current guest data remain UNKNOWN after prior LXD socket read denial. No kernel, nft, systemd, Owner Gate, executor, Network or Cloud operations were performed. **P0 OPEN / G-STANDALONE BLOCKED.**

## Core P0 DONE producer-schema and READY-deadline consistency — offline RED→GREEN (2026-10-15)

**VERIFIED VM-ONLY READ-ONLY REVIEW SOURCE, NOT A NEW LIVE KVM OR ROLLBACK PROOF.** The [rollback review `classify`](../../scripts/lab/vm/guest-rollback-review.py) previously checked the primary DONE mainly by `status="AUTO_ROLLBACK_CONFIRMED"` and both DONE paths by stage/boot/receipt epoch. It accepted otherwise unexpected data such as `ownerApproved: true`, `signedOwnerReceipt: true`, `kernelWrites: true`, an invented fallback schema, malformed/nonfinite monotonic clocks or a DONE deadline differing from watchdog READY, then returned the positive **`SYNTHETIC_OBSERVATION_CHAIN_CONSISTENT_NOT_AUTHORITY`** label. This was a misleading classification despite the result's independent fixed safety flags remaining false.

The reviewer now defines exact, separate **producer-derived** field sets from [primary DONE in `guest-auto-watchdog.py`](../../scripts/lab/vm/guest-auto-watchdog.py) and [fallback DONE in `guest-fallback-supervisor.py`](../../scripts/lab/vm/guest-fallback-supervisor.py). The source-only `matches_producer_done` check rejects unknown/absent properties, verifies fallback schema `lightluna.vm-fallback-done/v1alpha1`, preserves fallback netns and explicit owner/synthetic flags, rejects booleans and nonfinite monotonic values, and requires DONE `deadlineMonotonic` to equal READY's deadline. The classifier returns **`DONE_METADATA_MISMATCH_REVIEW_REQUIRED`** for these faults; a writer/status mismatch retains the existing `DONE_STATUS_OR_WRITER_CONTRADICTION` classification. Both legitimate producer-shaped fixtures remain labeled consistent **NOT AUTHORITY**, and all result flags `kernelWrites=false`, `autoReconciliationAllowed=false`, `ownerApproved=false`, `signedOwnerReceipt=false`, `successAcknowledged=false` remain enforced.

New [offline reviewer tests](../../scripts/lab/vm/test_rollback_review.py) reproduced **11 negative subcases RED** on the old code (forged authoritative flags/extra fields, fallback fake schema, both writer deadlines differing from READY, and boolean/Infinity time fields), then GREEN after correction. The focused review suite is **28/28 PASS** and complete VM Python **offline** suite is **113/113 PASS**. Earlier KVM observations in this document are **historical** only; no live KVM, LXD, watchdog, nft, power-loss or network test was run during this change.

**Limit:** Exact DONE JSON properties and deadline equality validate declared fixture consistency, not immutable cryptographic producer identity, trusted clock sampling, receipt/journal fsync atomicity, independently authenticated Owner approval, safe host firewall apply or guaranteed management rescue. Existing guest inventory is UNKNOWN because authorized read-only LXD socket access was previously denied; no bypass or cleanup. **P0 OPEN / G-STANDALONE BLOCKED; NetBird/Cloud deferred, ADR-029 parked.**

## Read-only FD-held network namespace visibility — KVM isolated PASS (2026-10-14)

**Scope and source baseline:** `feat/p0-standalone-foundation@d909ce4ce9c0172e87ab4568b8e2defabfc292a1` on HOMESV. The dedicated read-only [guest boot inspector](../../scripts/lab/vm/guest-boot-inspect.py) and [rollback reviewer](../../scripts/lab/vm/guest-rollback-review.py) now require an additional `foreignNetnsFdHolders` inventory field. The inspector checks the namespace inode referenced by every visible process and scans bounded `/proc/<pid>/fd` descriptors. A foreign `net:[inode]` target or an **nsfs device/inode differing from PID1's network namespace** is treated as an **unresolved namespace holder**. The nsfs fallback is deliberately conservative: a file descriptor of another namespace type sharing nsfs cannot be proven to be a network namespace from inode alone; it therefore prevents a false all-clear instead of declaring safety. Missing/malformed new inventory fields are denied by both classifiers.

**Real no-NIC KVM proof:** [explicit-ACK test runner](../../scripts/lab/vm/run-fd-held-netns-review.sh) guarded the exact KVM profile, independent kernel, guest identity and `lo` only. Inside the guest, it created a disposable `ip netns`, opened a read-only FD, deleted its `/run/netns` name while **remaining in PID1's original network namespace**, and verified that ordinary process-netns, named-netns and root nft inventories still appeared empty. Under Linux, `readlink(/proc/self/fd/N)` for this bind-mounted nsfs FD displayed the original path before deletion and `/` afterward; the open FD's `st_dev/st_ino` still identified the foreign nsfs namespace. The improved inspector detected `foreignNetnsFdHolders >= 1`, and the read-only rollback classifier returned `KERNEL_STATE_PRESENT_OR_UNKNOWN`, `kernelWrites=false`, `autoReconciliationAllowed=false` **despite a valid terminal journal/receipts/DONE**. The test closed the FD with a `finally` cleanup and verified no named namespace, root nft table, or foreign FD holder remained and the active journal SHA-256 was identical before/after. **No nft rule was installed or modified during this test.**

**Offline validation:** five new tests (3 boot inspector, 2 rollback reviewer) cover FD-held namespace rejection, absent legacy field rejection and wrong field type. Combined VM Python suite **91/91 PASS**. An earlier live test assumed readlink returned `net:[...]` and stopped at that incorrect assumption; no false PASS was recorded and VM namespace cleanup was independently checked. The corrected nsfs inode-based test exited 0 with `VM_FD_ONLY_FOREIGN_NETNS_DETECTED_AND_REVIEW_DENIED_PASS` and `VM_FD_NS_CLEANUP_JOURNAL_HASH_UNCHANGED_NO_NFT_PASS`.

**Critical limitations:** bounded `/proc` scan is still a race-prone best-effort guest-only inventory, **not a forensic kernel enumeration**. Permission errors, scan overflow or unsupported namespace representations must fail closed; hostile root/kernel could hide objects. No FD-backed network namespace is deleted by the inspector. Do not infer every possible namespace is absent merely because this test passed. No production daemon, real firewall/host nft action, Cloud/NetBird integration or cross-boot automatic recovery has been authorized. **P0 OPEN; G-STANDALONE BLOCKED.**

## VM synthetic receipt file/directory fsync and ENOSPC injection (2026-10-14)

**Status: offline + guest-local filesystem tests PASS, NOT physical disk/power-loss proof.** Baseline Git parent `feat/p0-standalone-foundation@98e4a1775d975b11a438aea150b09cd2754ed600`. The new [receipt fault tests](../../scripts/lab/vm/test_rollback_fsync_faults.py) instrument `os.fsync` to raise a **synthetic** `EIO` at either the file or parent-directory fsync boundary of the existing [receipt writer](../../scripts/lab/vm/guest-rollback-receipts.py). They also inject `ENOSPC` before file open, corrupt a partially written JSON record, and verify that a preexisting observation epoch is not overwritten. No physical disk fault is introduced; this is **callsite/error propagation** testing, not empirical filesystem crash consistency.

The separate [explicit-ACK guest runner](../../scripts/lab/vm/run-receipt-fsync-lab.sh) checks **exact** `light-luna-p0-nftvm` KVM identity, kernel separation, VM marker and loopback-only NICs, then requires a **terminal** synthetic journal and empty guest root nft/named netns before running. Tests allocate **temporary guest directories** and monkeypatch the receipt module's `ROOT` to those directories; none call `nft`, create a live firewall rule, mutate the active stage journal or produce production receipts. The runner compares SHA-256 of the active guest journal **before/after** and verifies no root nft tables or named netns afterward.

**Observed:** 10/10 filesystem fault tests PASS offline, and **10/10 PASS inside the no-NIC guest** with runner exit 0. Specifically, simulated `prepared` file/dir fsync failure or pre-open `ENOSPC` interrupts the call before a **modeled** kernel write, while errors at `kernel-absent` or `journal-terminal` propagate without writing a synthetic DONE. An already created partial/orphan receipt is never overwritten on retry. A truncated JSON receipt is rejected. Historical epochs are retained.

**Important unresolved ambiguity:** a newly visible, valid-looking receipt file can exist **even when its fsync operation returned EIO or the parent-directory fsync did not complete**. The read-only receipt parser cannot infer durable storage from parseable bytes. On a process crash, such an observation needs explicit external review; it is not automatically repairable or equivalent to a signed success acknowledgment. This fault matrix does **not** execute primary/fallback service kill or nft rollback on the fault path, test real ENOSPC/full filesystem, simulate actual power interruption, or validate ext4 journal ordering under a crash. Future work must cover those separately. **P0 OPEN; G-STANDALONE BLOCKED.**

## Cooperative rollback single-writer flock — bounded KVM proof (2026-10-14)

**Development verification only. Baseline:** HOMESV `feat/p0-standalone-foundation@b8b32fe0b8a3853ff02fc3bb7f67316bb4d9623c`. [Rollback fence source](../../scripts/lab/vm/guest-rollback-fence.py) provides a persistent, VM-local POSIX `fcntl.flock(LOCK_EX)` on `synthetic-rollback-fence.lock`, opened `O_NOFOLLOW` with `0600` permissions and guarded against symlink/inode/owner/hardlink substitution. Lock acquisition has a bounded 3-second wait, with fail-closed timeout. Once held, the helper reloads journal and validates the current Linux boot ID, stage ID and complete ordered history including the terminal history entry.

Both the original [primary watchdog](../../scripts/lab/vm/guest-auto-watchdog.py) and independently netns-pinned [fallback](../../scripts/lab/vm/guest-fallback-supervisor.py) now **cooperatively hold this same lock** from journal observation and kernel table check through fixed guest-netns nft deletion, `ROLLED_BACK` journal fsync and their distinct DONE receipt fsync. A contender must re-evaluate journal **inside the lock**; it cannot base a rollback decision on an earlier unlocked `COMMITTED_SYNTHETIC` observation. For noncommitted/unrecognized state the primary refuses kernel writes; the fallback records a REJECTED reason instead of a false DONE.

**Offline evidence:** [10 rollback-fence tests](../../scripts/lab/vm/test_rollback_fence.py) exercise independent forked process contention, timeout refusal, release/second writer entry, stage and boot mismatch, malformed/mismatched/empty history, symlink and unsafe lock permissions. This is POSIX advisory locking, **not** a durable owner epoch or signed authority. Kernel writes by non-cooperating root processes and stage `init/VALIDATED/COMMITTED` transitions remain outside this lock.

**Actual no-NIC KVM evidence:** [acknowledged 2-mode fault runner](../../scripts/lab/vm/run-fallback-faults.sh) again PASS for keeper and watchdog postcommit SIGKILL after fencing: fixed synthetic table removed, guest IPv4/IPv6 TCP/UDP restored and fallback DONE. The [dual-arm experiment](../../scripts/lab/vm/run-race-crash-tests.sh) also ran with the fallback attempting at the **same monotonic deadline** as primary, and produced only primary DONE plus an explicit fallback REJECTED status; both services were prearmed before synthetic commit. A further deliberate `os._exit(72)` **inside the lock after nft deletion** demonstrated kernel table absent but journal still `COMMITTED_SYNTHETIC` and no success DONE. Process exit releases `flock`; it does **not** repair this gap. A missing-ACK archival attempt was rejected, followed by separately acknowledged preservation under a unique evidence tag, never relabeling journal `ROLLED_BACK`. These are finite observed lab runs, not a statistical concurrency guarantee.

The normal independent KVM full suite subsequently PASS with primary autonomous TTL and original packet probes; the old shell fixture sometimes emits nonfatal `wait_for: No record of process` and remains an open harness issue. **Still blocked:** signed owner authorization, durable monotonic fencing epoch, multi-process transaction commit across nft/kernel and disk, mid-journal fsync/reboot/power-loss, simultaneous arbitrary competing writers, generic namespace/real NIC safety, product privileged executor and release. **P0 OPEN; G-STANDALONE BLOCKED.**

**Case A — primary/fallback both READY, primary remains healthy (`primary_race`).** Both independent PID1-managed processes were armed before the synthetic table was installed. At TTL the primary watchdog removed the table, journal reached `ROLLED_BACK` and primary emitted `AUTO_ROLLBACK_CONFIRMED`; at deadline + 1s the fallback observed the already terminal journal, recorded `PRIMARY_ALREADY_TERMINAL_NO_TAKEOVER` as **rejection**, emitted no fallback DONE and did not attempt a second deletion. IPv4/IPv6 TCP/UDP were restored. This is *one controlled dual-armed arbitration observation*, **not** a simultaneous last-millisecond race test or multi-process lock proof.

**Case B — fallback exits after nft deletion but before journal/DONE (`fallback_after_delete`).** The primary watchdog was SIGKILLed after an observed synthetic drop; the independently pinned fallback verified the strict fixed nft shape, deleted the guest synthetic table and checked absence, then deliberately called `os._exit(72)` at the exact **VM-only failpoint** before `guest-stage-journal.py` advances state. After the monotonic deadline, [guest fault observer](../../scripts/lab/vm/guest-fault-evidence.py) saw that the fallback service MainPID had exited, the synthetic table was absent, **journal still `COMMITTED_SYNTHETIC`**, and neither primary nor fallback had a success DONE. It wrote fsynced `FAILURE_DETECTED_NOT_RECOVERED` evidence with `kernelAbsentJournalIncomplete=true` — not `AUTO_ROLLBACK_CONFIRMED`. The stage-test EXIT handler subsequently cleaned only the temporary namespaces. [Manual archive](../../scripts/lab/vm/guest-archive-fault.py) rejected missing ACK, and on explicit ACK preserved the original incomplete journal and fault record unchanged; the fallback READY was separately saved under a unique tag. The runner exited zero with `VM_RACE_AND_AFTER_DELETE_CRASH_CONSISTENCY_DETECTED_PASS`.

**Measured safety boundary:** fail-closed *observation* of the commit/kernel divergence, not repaired atomicity. After both cases the VM was checked: only `lo`, root nft inventory empty, no named guest test netns, active journal archived, and unique test evidence retained in the VM. The existing single-controller JSON journal has no ownership fencing, multi-writer lock or atomic kernel+disk commit. **Post-fault default KVM regression** also completed with exit code 0 and no stderr: original unhooked `nft -c`, independent explicit revert, primary TTL autonomy and synthetic IPv4/IPv6 TCP/UDP accepted/dropped/restored as expected. This regression does **not** repair the separate observed after-delete journal inconsistency. **Open gates:** crash during nft write/delete, crash after journal fsync before DONE, primary-vs-fallback simultaneous delete race, fallback reboot/power-loss, fd-held/foreign netns and hostile-root cases. No production self-healing, signed authority, installer or remote reachability claim. **P0 OPEN; G-STANDALONE BLOCKED.**

## Independent VM-only fallback after keeper/watchdog SIGKILL — lab pass (2026-10-14)

**Verification, not a production recovery system.** Starting from development baseline `feat/p0-standalone-foundation@73518264e2e9de2e2926fc482fc4421fe452701e`, the [independent fallback prototype](../../scripts/lab/vm/guest-fallback-supervisor.py) is launched as its own PID1-managed systemd transient service **before** synthetic nft commit. It executes `nsenter -n` once while the verified keeper is still alive, then **holds the guest test netns itself**; subsequent rollback does not need the keeper PID to remain available. The fallback matches primary watchdog's boot ID, stage ID, TTL deadline, keeper process start ticks and target netns inode and produces an fsynced READY file before any commit.

After deadline + 1 second, it checks the current boot and **its own** netns inode, exact stage journal and whether the named primary watchdog or keeper process has died. Only when `COMMITTED_SYNTHETIC` remains outstanding does it inspect the **exact nftables JSON** from the guest-only netns: one fixed `inet luna_p0_stage` table, one input chain with filter/input/-50/accept, and exactly three matching synthetic IP+TCP:18080, IP+UDP:18081 and IPv6+ICMPv6 echo-request counter+DROP rules. Foreign chain, changed port/source, added/duplicate rule or reordered expression is denied. It can delete **only** that fixed test table, confirm absence, atomically progress the single-controller journal to `ROLLED_BACK` and write its own `SYNTHETIC_FALLBACK_ROLLBACK_CONFIRMED` receipt. It never accepts a table name from an external request. This is a **VM-only privileged prototype** and not owner-approved Light Luna policy execution.

The [explicit-ack host runner](../../scripts/lab/vm/run-fallback-faults.sh) exercised **two actual SIGKILL cases** in the same exact no-NIC KVM VM: `keeper_postcommit` and `watchdog_postcommit`. In each, packet drop counters were positive before the fault, the primary DONE was absent, and the independent fallback returned positive evidence **before the existing test EXIT cleanup**, restoring synthetic IPv4/IPv6 TCP/UDP and terminal journal. Two runs of both cases PASS, including the second run using a strictly verified nft JSON rule shape. The runner retains per-mode/verification-tag records without overwriting earlier test evidence. After the last run, guest had only `lo`, empty root nft/named netns and `ROLLED_BACK` journal. **A full independent normal KVM regression also completed with exit code 0**, including nft syntax, IPv4/IPv6 packet probes and primary autonomous TTL rollback without enabling fallback. One nonfatal legacy ICMP shell `wait_for: No record of process` stderr diagnostic remains an open harness reliability item. A missing fallback-ACK negative call was also denied **before journal mutation**, leaving the last terminal `ROLLED_BACK` state unchanged.

[Offline parser negative tests](../../scripts/lab/vm/test_fallback_supervisor.py) cover 12 synthetic rule-shape cases (including changed port, source and duplicate rules). A real KVM nft JSON probe was used to determine expected shape, and its temporary table/netns were removed immediately afterward. **Not yet proven:** fallback service death, failure during nft delete↔fsynced journal/DONE, malicious root/FD-held namespace, concurrency, actual power loss/reboot, packaging or health-managed service restarts; primary completion racing fallback also needs explicit live testing. Existing service-death detection tests without opt-in fallback are historical independent evidence, not invalidated. **P0 OPEN, G-STANDALONE BLOCKED.**

## Why the first watchdog attempt was not accepted

Earlier source code proved only that a **separately triggered service** can undo a synthetic nft rule. It did **not** prove a service autonomously fires when TTL expires. Attempts using detached `setsid`, `systemd-run` with an internal `sleep`, and transient systemd timers intermittently failed to complete. Their failures were recorded and the gate remained open.

We identified two independent VM-test harness concerns:

1. `ip netns` names created from `lxc exec` may not be visible in the VM's systemd PID1 **mount namespace**. A rollback service cannot rely on a named netns being visible. The systemd process must target the network namespace of a **verified process PID**.
2. A test shell's short-lived background PID could disappear when the simulated controller terminated. The guest suite now uses a **PID1-managed systemd namespace keeper** started via `nsenter -t <initial-anchor-pid> -n sleep 240`. It validates `/proc/<keeper-pid>/ns/net` matches the expected namespace inode before terminating the original controller-owned anchor. [Keeper smoke fixture](../../scripts/lab/vm/guest-keeper-smoke.sh) explicitly demonstrated the keeper survives that original anchor being terminated. Both legacy ICMP and new stage tests use the keeper. Cleanup is scoped to the **top-level Bash PID** to prevent child/subshell exit traps stopping the keeper early.

## State and deadline sequence

```text
HOMESV (nonprivileged CLI)                   KVM guest without NIC
        │                                        │
 typed inert manifest --------------------> exact schema/hash/TTL validation
                                               STAGED → VALIDATED
                                               │
                                independent systemd keeper holds target netns
                                               │
                           watchdog (PID1) checks expected PID birth + net inode
                                               │
                           verifies synthetic table does not yet exist
                                               │
                 atomic READY with monotonic arm/deadline/TTL and stage ID
                                               │
                    test refuses commit unless >=5s before expiry
                                               │
             ONLY FIXED GUEST-NETNS SYNTHETIC nft hook applied
                                               │
                            journal COMMITTED_SYNTHETIC
                                               │
                            positive drop counters and probes
                                               │
                            simulated controller terminated
                                               │
                           watchdog wakes at monotonic deadline
                                               │
                     verify keeper PID birth+netns inode again
                                               │
                     nft delete ONLY `inet luna_p0_stage`
                                               │
                         verify table no longer exists
                                               │
                       journal terminal ROLLED_BACK
                                               │
                    atomic DONE receipt with elapsed/lag evidence
                                               │
                   verify IPv4/IPv6, TCP/UDP probes restored
```

The deadline is **relative to arming**, not commit. This is intentionally conservative: commit occurs only if there are at least five seconds remaining. The lab requires `DONE.status=AUTO_ROLLBACK_CONFIRMED`, journal terminal `ROLLED_BACK`, no nft table after cleanup, and measured monotonic completion lag ≤3.5s. These numeric limits are **test acceptance settings**, not an SLA or guaranteed production latency.

## Safety behavior / negative cases

- When PID, process birth time or network namespace inode changes before rollback, **refuse unsafe namespace entry** rather than possibly modifying an unrelated namespace. This needs a separate rescue solution in the eventual product, because refusing the wrong target is not the same as restoring a valid target.
- If a transaction is not actually committed at expiry, no success receipt is recorded; a synthetic table seen unexpectedly is still removed in a fail-closed way.
- If journal is corrupt, missing or a table disappears before verification, do not issue `AUTO_ROLLBACK_CONFIRMED`.
- The separate service never accepts a table name from the product or user; it can touch only the fixed `luna_p0_stage` table in the verified VM target namespace.
- No LXD NIC, LXD bridge, host nft apply, Cloud, NetBird, live WAF or eBPF/XDP involvement.
- Reconciliations after interrupted negative test runs are **manual and evidence-based**; no silent journal reset.
