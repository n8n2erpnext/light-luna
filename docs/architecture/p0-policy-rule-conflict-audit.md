## Explicit JSON null fail-closed PolicyBundle decode — Core P0 (2026-10-15)

**IMPLEMENTED SOURCE-ONLY TRUST-BOUNDARY CORRECTION, NOT A FIREWALL EXECUTOR.** A typed Go JSON decoder normally accepts explicit `null` for many non-pointer fields and decodes them as their zero values. Before this patch, the public [JSON Schema](../../schemas/policy-v1alpha1.schema.json) rejected `spec.rules: null`, `spec.aliases: null`, nullable optional `rules[].note`, `destinationPort`, `autonomous.maxBanTtlSeconds` and several other fields, but the **real `lunactl firewall policies validate` accepted them** whenever the resulting zero-valued Go Bundle met semantic checks. `rules: null` was particularly confusing: an explicitly invalid policy list was silently interpreted as no rules. An eight-case [Go PolicyBundle regression](../../internal/policy/policy_test.go) observed **RED in seven cases** (the `null` alias element was already rejected), while direct CLI/schema probes also confirmed inconsistent outcomes.

[Shared bounded JSON parser](../../internal/strictjson/decode.go) now offers opt-in `DecodeRejectNull`, which reuses the existing duplicate-key, depth, strict-unknown-field, size, and trailing-data checks while rejecting `null` tokens at **any nesting depth** during token traversal. [PolicyBundle.Decode](../../internal/policy/model.go) adopts this stricter entrypoint; other applications of `strictjson.Decode` remain backward-compatible. [Strict parser tests](../../internal/strictjson/decode_test.go) cover root, nested maps and arrays, non-null zero/false/empty values, retained legacy decode semantics, and duplicate-key denial. Go PolicyBundle tests are now GREEN, and the [real CLI/schema matrix](../../scripts/test_p0_policy_schema_contract.py) adds nine explicit-null negatives to the prior 38 cases: **47/47** matched both Draft 2020-12 and offline-built `lunactl` on HOMESV.

**Preserved semantics:** an **omitted** optional property, numeric zero, boolean false, or a genuine empty non-null list still follows existing schema and Go validation rules; only an **explicit JSON `null`** is rejected by PolicyBundle Decode. This closes a preflight/Go ambiguity but does not prove full schema equivalence, kernel verdict, independent emergency network reachability, owner authorization or rollback. No privileged executor, nft APPLY, NetBird, Cloud or ADR-029 change; **P0 OPEN / G-STANDALONE BLOCKED**.

## Policy metadata revision int64 schema boundary — Core P0 (2026-10-15)

**IMPLEMENTED DEVELOPMENT VALIDATION / NO PRIVILEGE OR KERNEL SIDE EFFECTS.** The authoritative [Go PolicyBundle model](../../internal/policy/model.go) stores `metadata.revision` in signed `int64`, and [`Bundle.Validate`](../../internal/policy/validate.go) requires revision at least 1. The public [JSON Schema](../../schemas/policy-v1alpha1.schema.json) previously had a lower bound but **no upper bound**, so Draft 2020-12 accepted `9223372036854775808` and even integers with dozens of digits that the Go CLI cannot decode.

The schema now requires an integer between **1 and 9223372036854775807 inclusive**, preserving the Go type's representable positive range. A [Go decoding regression](../../internal/policy/policy_test.go) tests max `int64` success and rejects overflow, very large, zero and negative revision values. The existing [Python contract matrix](../../scripts/test_p0_policy_schema_contract.py) adds six matching revision cases to its 32 existing rescue/port/alias/note cases; the suite was observed **RED** on the old schema at `int64 overflow`, then **GREEN (38/38)** with `--verify-cli` building and running the real offline `lunactl firewall policies validate` on every identical synthetic JSON policy.

**Limit:** JSON Schema's mathematical `integer` definition need not fully capture the textual JSON number syntax accepted by Go's `int64` decoder. This is bounded test agreement, not exhaustive schema/Go equivalence or policy safety. No owner approval, nft write, real rescue reachability, NetBird or Cloud work. P0 OPEN; G-STANDALONE BLOCKED.

## Cross-engine note-NUL rejection and real CLI parity matrix (2026-10-14)

**IMPLEMENTED AS PUBLIC POLICY SCHEMA VALIDATION + OFFLINE CONTRACT TESTS; NO KERNEL WRITE.** The Go [`Bundle.Validate`](../../internal/policy/validate.go) rejects a U+0000 NUL byte in `rules[].note`, but the public [JSON Schema](../../schemas/policy-v1alpha1.schema.json) previously accepted this field. The Python Draft 2020-12 contract test reproduced **RED** (`note/NUL in note`: schema valid, expected invalid) before correction. The schema now prohibits a NUL anywhere within the optional note via `not: {pattern: "\\u0000"}`, while preserving ordinary, newline, empty and 512-byte ASCII notes.

The existing [schema contract script](../../scripts/test_p0_policy_schema_contract.py) now checks **32 bounded scenarios** (11 rescue declaration, 12 protocol/port, two reserved-`any` alias and seven note cases). `python3 scripts/test_p0_policy_schema_contract.py --verify-cli` **additionally builds an offline unprivileged `lunactl` binary and runs `firewall policies validate` on every exact JSON fixture**, comparing the real Go exit result against schema and the expected outcome. On HOMESV both schema-only and CLI parity checks PASS; no simulated Go acceptance values are substituted for the actual binary. The temporary executable and synthetic JSON files are deleted at script exit.

**Known limits:** The 32-case matrix tests only shared, explicitly chosen semantics, not full Go/schema equivalence. In particular, Go's `len(note)` measures UTF-8 bytes while JSON Schema `maxLength` measures Unicode code points, so multibyte notes may pass schema but fail Go; the Go validator remains final authority. Neither validation layer proves firewall/network effect, emergency management reachability, authenticated human owner nor executor permission. P0 OPEN / G-STANDALONE BLOCKED.

## Conflict report warnings carried inside JSON — static Core audit hardening (2026-10-14)

**IMPLEMENTED DEVELOPMENT SOURCE / REPORT-ONLY.** The bounded [`AnalyzeConflicts`](../../internal/policy/conflicts.go) previously returned machine-readable `COMPLETE_NO_FINDINGS`, `FINDINGS_REQUIRE_REVIEW` or `INCOMPLETE_REVIEW_REQUIRED` without including its *nonclaims* inside the JSON result. This could mislead a downstream consumer into interpreting a clean static analysis as proof of kernel behavior, emergency-access reachability or authorization.

The additive `warnings` array now accompanies **every successful conflict report**, including early returns when the pair/comparison/finding budget is exhausted. It explicitly says that (a) effective kernel verdicts and third-party firewall coexistence are unverified; (b) `emergencyAccess` CIDRs are declarations, with independent management/rescue reachability UNKNOWN; and (c) no owner identity or executor authority is granted by this report. These warnings are not extra findings and do **not** change `Status`, `Complete`, `LimitedBy`, limits or the analyzer's conflict algorithm. CLI `firewall policies analyze` serializes the fields without changes to `KernelWrites=false` and `Enforceable=false`.

[Three-case Go regression](../../internal/policy/conflicts_test.go) was observed **RED → GREEN** across a complete clean result, a complete finding, and pair-budget incomplete result. Real development CLI output confirmed warnings are present on the baseline fixture. No policy apply/rollback, privileged API, proof of owner consent, independent network rescue, NetBird, Cloud or monitoring was added. **P0 OPEN / G-STANDALONE BLOCKED.**

## Protocol/destination-port schema parity — bounded P0 source check (2026-10-14)

**IMPLEMENTED IN PUBLIC JSON SCHEMA + REGRESSIONS, NO PRIVILEGED POLICY EXECUTION.** The existing Go [`Bundle.Validate`](../../internal/policy/validate.go) defines `destinationPort=0` as the wildcard for TCP/UDP, and only `0` (or omitted) is permitted for ICMP/ICMPv6. The previous [public JSON Schema](../../schemas/policy-v1alpha1.schema.json) contradicted both halves: it rejected explicit port `0` and accepted nonzero ICMP/ICMPv6 ports. These mismatches were verified independently with Draft 2020-12 validation before editing.

The schema now permits numeric `0..65535` for `destinationPort` and uses an `if/then` limited to `protocol=icmp|icmpv6` to require `destinationPort=0` when the optional field is present. TCP/UDP port 0 remains a declared wildcard; ICMP with no port remains valid. [Go semantic unit matrix](../../internal/policy/policy_test.go) covers ten protocol/port cases, while the repeatable [Python schema contract check](../../scripts/test_p0_policy_schema_contract.py) covers twelve (including omitted optional ports), on top of eleven rescue cases and two reserved-alias negatives. The schema matrix was **RED on prior schema** (TCP wildcard 0 rejected) and **GREEN after patch**; Go/nft-preview/flow-sim tests PASS.

**Caveats:** These are declarative protocol/port semantics in a simplified P0 policy model, not packet-path, conntrack, rule interaction, full Go/schema equivalence or kernel-proof tests. No Gate authority, rescuer validation, actual nft call, NetBird, Cloud or telemetry changed. P0 remains OPEN; G-STANDALONE BLOCKED.

## Deny-default rescue-declaration parity — public schema and Go Core (2026-10-14)

**IMPLEMENTED IN SOURCE; SCHEMA PREFLIGHT ONLY, NOT RESCUE REACHABILITY.** [Go policy validator](../../internal/policy/validate.go) already requires `defaultInbound=drop|reject` to have `emergencyAccess.enabled=true` **and** a nonempty `emergencyAccess.networks` list. However, the public [policy JSON Schema](../../schemas/policy-v1alpha1.schema.json) previously accepted deny-default bundles with `enabled=false`, no networks, or both. This was reproduced on HOMESV: four invalid negative combinations passed Draft 2020-12 schema validation while Go correctly rejected them.

The schema now has a scoped `if/then` under `spec` for `drop` or `reject`, demanding both the enabled flag and at least one declared network. It deliberately allows `accept` with disabled/empty rescue; the existing Go `Bundle.Validate` implementation was **not changed**. A new [Go semantic matrix](../../internal/policy/policy_test.go) covers ten allowed/denied combinations, and a standalone [Python schema contract regression](../../scripts/test_p0_policy_schema_contract.py) covers eleven deny/accept rescue cases plus both reserved `any` alias-type negatives. The schema script showed RED on the original schema (invalid `drop` with rescue disabled accepted) and GREEN after the correction; Go tests stayed PASS. Python script requires an installed `jsonschema` library. It tests **only this bounded parity matrix**, not full equivalence between schema and Go validation.

**Safety limits:** At least one configured CIDR is merely a declaration. No actual SSH reachability, independent break-glass access, management network route, kernel nft policy, live canary, automatic fallback, owner authorization or host compatibility was validated. The public JSON Schema is not a privilege gate: Go remains authoritative, and even a valid policy does not authorize APPLY. Core P0 remains OPEN; G-STANDALONE BLOCKED, NetBird deferred, ADR-029 parked.

## Reserved "any" source and alias collision — fixed at validation boundary (2026-10-14)

**IMPLEMENTED DEVELOPMENT GO VALIDATION + SCHEMA, NOT ENFORCEMENT.** The rule source literal `"any"` is a reserved wildcard. Before this correction, `Bundle.Validate` could accept a `cidr-set` alias literally named `any`. [ConflictAnalyzer](../../internal/policy/conflicts.go) and [Flow Simulator](../../internal/flowsim/simulate.go) interpret `source: "any"` as a wildcard **before** alias lookup, while [nft preview](../../internal/nftpreview/compile.go) expands an alias named `any` into CIDRs. That created incompatible interpretations of the same syntactically valid policy, even though none of these P0 components applies firewall rules.

The [authoritative validator](../../internal/policy/validate.go) now rejects the alias ID `any` for **both** CIDR and port sets, including an unused alias. The [public JSON Schema](../../schemas/policy-v1alpha1.schema.json) rejects the same reserved name via `not: {const: "any"}` on alias IDs. Ordinary rules with `source: "any"` remain valid when no alias collides. [Go negative and positive tests](../../internal/policy/policy_test.go) were observed RED→GREEN for the CIDR collision; a second regression rejects the unused port-set collision, and both `MakePreview` and `AnalyzeConflicts` fail validation rather than offering misleading output. The Python `jsonschema` Draft 2020-12 validator confirmed schema validity, the baseline fixture, and both alias-collision negatives.

**Known open analyzer limitation:** A separate attempted multi-earlier-rule collective-union analyzer extension was **blocked by tool safety controls before implementation**; its uncommitted failing tests were removed, leaving no partial code or claimed acceptance. The existing implementation remains restricted to multiple CIDRs **within one earlier rule**, not a union of multiple earlier rules. Do not treat a zero-finding analysis as exhaustive. No kernel rule, privileged executor, rescue, owner approval, NetBird or monitoring feature was introduced. P0 OPEN, G-STANDALONE BLOCKED.

## Core change, not an enforcement feature

**Validator fix:** `Bundle.Validate` now rejects `icmp` with an IPv6 source and `icmpv6` with an IPv4 source, for literal CIDRs **and every member** of a referenced `cidr-set` alias. `any` remains family-neutral, while the selected protocol establishes its IPv4/IPv6 family. Non-ICMP TCP/UDP rules can remain dual-stack where the existing schema permits. No new schema field or port-set selector was introduced. Validation is now consistent with existing `nftpreview.render` and `flowsim.Fixture.Validate`, so the CLI `validate/preview` cannot approve an ICMP source that the nft compiler rejects later.

**Pure static rule audit:** [`policy.AnalyzeConflicts`](../../internal/policy/conflicts.go) validates the bundle, sorts by ascending unique `priority`, then compares pairs with matching direction/protocol. An earlier terminal `accept/drop/reject` can mask a later rule; an earlier `log` is nonterminal and cannot shadow. CIDR-set and `any` selectors are expanded within fixed limits; IPv4-vs-IPv6 are never overlapping. TCP/UDP port 0 is a wildcard. Findings:
- `LATER_RULE_SHADOWED`: one earlier terminal rule certainly covers the later source and port (including same-action redundancy or a later `log`).
- `DIFFERENT_ACTIONS_OVERLAP`: different actions overlap, but full shadowing was not proven; **a narrow allow before a broad drop is a reviewable intended exception**, not automatically invalid or dangerous.
- Zero findings means **only no pairwise issue detected within this simplified declared-policy model**, not no lockout risk, verified real rescue route or safe kernel policy.

**Bounded completeness:** hard ceilings of 8,192 rule pairs, 100,000 prefix comparisons and 128 findings. If exhausted, `Complete=false`, `Status=INCOMPLETE_REVIEW_REQUIRED`, and `LimitedBy` indicates why; never convert partial inspection to a false clean audit. Analyzing an otherwise valid large policy does not silently approve it. A single earlier rule's CIDR-set source **now supports exact, bounded union coverage** of a later CIDR by multiple same-family subnets, but **coverage by several different earlier rules together remains unmodeled**; this does not claim exhaustive policy/kernel equivalence.

CLI source: `lunactl firewall policies analyze <policy.json>` prints strict JSON `lightluna.rule-conflicts/v1alpha1`. `Enforceable=false`, `KernelWrites=false` for all completed or limited reports. **No HTTP listener, privileged IPC, nft call, file-write, actual rule application, Gate permission, signed owner approval, watchdog modification, NetBird or Cloud integration.**

## Bounded CIDR-set union coverage — Core continuation (2026-10-14)

**Implemented source-only extension**, parent Git `feat/p0-standalone-foundation@3d5a88cc1a190b7c39263fc85ad04b0539d6894e`: [`conflict_union.go`](../../internal/policy/conflict_union.go) derives inclusive last addresses for canonical IPv4/IPv6 prefixes and tests whether a sorted union of earlier-rule source intervals covers a later prefix **without gaps**. [`compareSources`](../../internal/policy/conflicts.go) still enforces `MaxCIDRComparisons=100000` while collecting source intervals and returns `INCOMPLETE_REVIEW_REQUIRED` on exhaustion. Prefix-set size stays bounded by `Bundle.Validate` (at most 256 alias members), and no IP iteration over a full /0 or /32/128 range occurs.

Examples: earlier `192.0.2.0/25` + `192.0.2.128/25` and later `192.0.2.0/24` now report `LATER_RULE_SHADOWED`; missing a /26 yields `DIFFERENT_ACTIONS_OVERLAP` if actions differ. Likewise, two IPv6 /33 parts can cover a /32; mixed IPv4/IPv6 entries cannot bridge address-family gaps. [`conflict_union_test.go`](../../internal/policy/conflict_union_test.go) includes positive/negative policy cases, exhaustive combinations of four /30 pieces of a /28 and four /128 pieces of a /126, plus IPv4/IPv6 address-space endpoint and comparison-budget tests. These are **bounded static correctness tests only**.

Limitations remain: an `any` later rule is treated conservatively rather than proving two-family full coverage; combining **multiple earlier terminal rules** is not analyzed as a collective union; connection state, kernel hook priority, Docker/UFW and emergency-access viability remain UNKNOWN. The analyzer cannot authorize owner approvals, ban/enforcement, nft operations or a claim that remote rescue is safe.
